# Oshepherd Vercel candidate

Generate this self-contained directory with `oshepherd supabase export-vercel
--wheel /path/to/the-current-wheel --output /path/to/empty-directory`. It carries
the verified local release wheel and locked runtime dependencies. Do not depend
on the currently published PyPI version for unreleased Supabase features.

Use Python 3.12 and a Hobby account for qualification. The function deadline is
150 seconds; the application keeps its conservative 135-second budget and
4,000,000-byte response cap. These are candidate settings, not hosted evidence.

Add the private `gateway.env` values generated by the operator installer to the
selected Vercel project's **Production** server environment. Keep the file outside
this deployment directory. The application requires `OSHEPHERD_BACKEND=supabase`,
`OSHEPHERD_GATEWAY_PROFILE=vercel`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` and
`OSHEPHERD_CLUSTER_ID`. No secrets belong in `NEXT_PUBLIC_*` or a Deploy URL.
Do not attach production credentials to Preview deployments: inference is denied
there by default. Explicit preview enablement requires an isolated cluster and
worker pool.

Install dependencies locally with `uv sync --locked`, then import `app:app` with
the explicit server environment. Vercel auto-detects the root FastAPI entrypoint;
no Uvicorn process, schema migration or permanent maintenance task runs on import
or during a build. Keep the independent maintenance runner running elsewhere.

After an authorized deployment, set its HTTPS origin as `gateway_url` in the
private operator connection file. Run `oshepherd supabase doctor`, then the
explicit `verify-inference --model <installed-model>` command. A deployment
protection/login page is not gateway readiness. Supabase Edge cancellation and
Vercel ingress/payload/duration measurements remain separate qualification gates.

This candidate has no public Deploy button yet. Publish a button only after the
release package/template and real hosted flow pass.
